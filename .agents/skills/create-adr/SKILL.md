---
name: create-adr
description: |
  ADR を作成する。
  Issue への対応仕様を策定する際や、更新する際に決定した設計判断に対して利用する。
  コードやドキュメントからは理由が読み取れない設計判断があった場合に利用する。
  コードコメントに残せるような軽微な設計判断はコードコメントに残すことを推奨する。
  既存ドキュメントに採用理由を追記すれば十分な場合は ADR を作成せずにドキュメントに追記することを推奨する。
---

指示に従って ADR を作成します。
ADR を作成するにあたって確認事項がある時は、ユーザーに質問して確認します。

以下のルールに従ってください。

- Markdown ファイルの内容は MADR フォーマットで作成する。
- 説明文は日本語で書く。
- 保存場所は `./docs/decisions` ディレクトリとする。
- ファイル名は `[YYYYMMDD]-[Issue番号]-[タイトル].md` とする。（例: `20260601-123-add-new-feature.md`）
  - 日付は Asia/Tokyo タイムゾーンの現在日時を使用すること。
  - ファイル名が MADR の仕様と異なるのは、複数の Issue 対応が並列で進む際に、連番だと番号が衝突する可能性があるため。
