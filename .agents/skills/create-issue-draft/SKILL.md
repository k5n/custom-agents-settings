与えられた要求をもとに、GitHub Issue 作成のための草案 Markdown ファイルを作成してください。

## ルール

- 日本語で記述してください。
- Issue 草案の出力先は `./docs/tmp/issues/` 配下としてください。
- 1 Issue につき 1 Markdown ファイルを作成してください。
- ファイル名は `NN-short-title.md` 形式としてください。
  - `NN` は 01 から始まる 2 桁の連番とし、分割した Issue の実施順を表してください。
  - `short-title` は Issue タイトルを短く要約した識別子とし、ASCII の kebab-case を優先してください。
  - 適切な識別子を安全に決められない場合は `issue` を用いて `NN-issue.md` としてください。
- 要求に対して複数の Issue に分割した方が良い場合は、複数の草案 Markdown ファイルを作成してください。
  - 1 つの Issue は数回の作業フェーズで完了する程度の規模感を目安としてください（通常は 1 から 5 回、ただしキリが良いことを優先）。
  - 1 回の作業フェーズは、詳細実装計画作成、テストを含む実装、レビューと修正、リファクタリングを行い、1 コミットする程度の規模感を目安としてください。
  - 分割した Issue に依存関係や推奨実施順がある場合は、各草案の備考に明記してください。
- 情報が不足している場合の扱いは以下の通りとしてください。
  - 草案の品質に大きく影響する情報が不足している場合は、先に確認質問を返してください。
  - 軽微な不足であれば、勝手に断定せず、前提や未確定事項として草案内に明記してください。
- 既存の Issue 草案ファイルがある場合は、今回の要求と関係するものだけを更新し、無関係なファイルは変更しないでください。
- Markdown ファイルの内容は、以下のテンプレートに必ず従ってください。
  - `title` を含む frontmatter を必ず出力してください。
  - `背景`、`概要`、`完了条件` は必須です。
  - `備考` は追加情報、前提、未確定事項、依存関係、参考資料がある場合に記載してください。
  - `完了条件` は検証可能な条件を具体的に記載してください。

## テンプレート

```markdown
---
title: [Issueタイトル]
---
## 背景

[Why?: なぜやるのか？このタスクが必要となった背景や、解決したい課題の説明。作業者が文脈を理解し目的を把握するための情報を提供する。]

## 概要

[What?: 何をするのか？このタスクで実装する内容の概要。作業者がタスクの全体像を把握できるように、具体的な作業内容や機能の説明を提供する。]

## 完了条件

[Definition of Done: 何をもってこのIssueを「完了（クローズ）」とするかの基準。]

## 備考

[この章はOptional: 追加の情報や参考資料、注意点や懸念点などがあれば記載する。]

```
